# M3 + M4 first cut: Q&A from your notes (v0.3.0)

v0.3.0 is the first build that answers questions. It covers the core of M3 (knowledge
base) and M4 (live loop): index sources, hear a question, show passages, stream a cited
Claude answer. The remaining parts of M3 and M4 are listed at the end.

## What it does

1. **Sources.** In Settings you add the two Anthropic doc presets (one click each), a
   folder of Markdown notes (an Obsidian vault works), or any `llms.txt` or page URL.
   Pages are fetched or files read, split by heading into passages with a
   `Title > Section > Subsection` label, and stored in a local SQLite index at
   `~/Library/Application Support/Jeeves/index.sqlite`.
2. **Hearing a question.** While listening, every time the remote speaker pauses for
   400 ms the provisional transcript of that utterance goes through a question detector.
   It looks for a question mark, a question opener ("how", "what", "can you", "is there")
   or a request phrase ("walk me through", "tell me about"), and ignores call logistics
   ("can you hear me?").
3. **Passages first.** The question is cleaned up for known mishearings ("cloud code"
   becomes "Claude Code") and searched locally (BM25). The top six passages appear in
   the answer panel straight away.
4. **Then the answer.** The passages, the last minute of transcript and the question go
   to Claude with the cached system prompt, and the answer streams in under the
   passages with [n] citations. If nothing matched, the panel says "Not in your notes."
   without calling Claude.

The **answer panel** floats above the browser on every Space and doesn't take focus
from it. It is hidden from screen sharing and screenshots, so people on the call can't
see it. It also has an **Ask** field for typed questions and an **Answer last** button
for when detection misses a question. Auto-answer can be turned off in the menu or in
Settings.

## Set-up (5 minutes)

```bash
curl -fL -o /tmp/Jeeves.zip https://github.com/mndrake/jeeves/releases/latest/download/Jeeves-macOS-arm64.zip
rm -rf /Applications/Jeeves.app && ditto -x -k /tmp/Jeeves.zip /Applications
open /Applications/Jeeves.app
```

1. Click the ear in the menu bar, then **Settings...**.
2. Paste your Anthropic API key (from platform.claude.com) and click **Save key**. It is
   stored in your login Keychain. After a Jeeves update, macOS may ask once whether
   Jeeves may use it: choose **Always Allow**.
3. Click **Add Claude API docs** and **Add Claude Code docs**. Indexing takes about
   30 s on a good connection; the summary line then reads roughly
   "2 sources, 532 documents, 18,000 passages".
4. Optional: **Add folder...** for your notes.
5. In **Test search**, type `how long does a cached prompt stay warm` and check that
   prompt-caching passages come back.

## Tests

| # | Test | Pass if |
|---|---|---|
| 1 | Answers panel → Ask: "how long does a cached prompt stay warm" | Passages appear immediately; answer starts streaming within about 1.5 s; it cites [n] and says five minutes by default |
| 2 | Ask: "does Claude Code support Rust plugins written in COBOL" | "Not in your notes." or a "Not covered" line, with no invented facts |
| 3 | Play a YouTube video of someone asking about the Claude API (or have a friend on a Meet call ask 5 questions from `eval/retrieval/questions.tsv`), Start listening | Questions are detected (blue "Question (...)" line in the menu) and answered in the panel |
| 4 | During test 3, say non-questions: "we moved the system prompt last week", "can you hear me?" | No answer is triggered |
| 5 | A question detection misses → **Answer last** | That utterance is answered |
| 6 | Share your screen in Meet with the panel visible | The panel is not in the shared image |
| 7 | Switch the model to Fast (Haiku 5.5) and Deep (Opus 5.5), ask test 1 again | Both answer; the footer shows the model, first-token time and cost |

Record per test: passages time, first-token time (both in the panel footer), and
whether the answer was right.

### Command-line checks (spike tools zip)

```bash
./spike-kb --db kb.sqlite --presets
./spike-kb --db kb.sqlite --eval retrieval/questions.tsv          # recall@1/3/6 and search latency
./spike-kb --db "$HOME/Library/Application Support/Jeeves/index.sqlite" --search "auto mode"
ANTHROPIC_API_KEY=sk-ant-... ./spike-kb --db kb.sqlite --ask "what does sonnet five five cost"
```

## Not in this cut (remaining M3/M4 work)

- **Embeddings and hybrid search** (M3). Retrieval is lexical only. The index already
  has the vector table; the embedding-model shoot-out comes next. Target: recall@3 at
  least 0.85.
- **Ingest-time enrichment** with Haiku 5.5 Batches: context prefixes and synthetic
  questions per passage (M3).
- **Incremental refresh**: re-indexing re-fetches the whole source (M3).
- **Global hotkeys** for "answer now" and "deeper" (M4). For now, use the panel buttons.
- **Follow-up merging**: a short follow-up ("and for Opus?") is answered on its own,
  using the transcript for context.
- **Latency instrumentation over 50 live questions**, the M4 exit criterion.
