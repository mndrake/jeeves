# M0 - Spikes and skeleton

Status: code complete; Mac measurements pending. Started 2026-11-01.

M0 proves each risky primitive in isolation on the target machine before M1-M4 build
on it. Everything below runs from this repository. The cross-platform parts are built
and tested on Linux; the macOS parts are written against Apple's macOS 26 SDK
documentation and **have not been compiled yet** (see "Not yet verified").

## What is in the repository

| Path | What it is | Builds on |
|---|---|---|
| `Package.swift` | SwiftPM package: library modules, four spike executables, tests | macOS 26+, Linux |
| `Sources/JeevesCore` | Monotonic clock, latency stats, CLI flags, transcript type, domain vocabulary | both |
| `Sources/AnthropicAPI` | Messages API client: SSE parser, request/stream types, `URLSession` streaming transport, answer profiles per mode, live-answer system prompt | both |
| `Sources/KnowledgeIndex` | SQLite wrapper, FTS5 + sqlite-vec hybrid index, reciprocal rank fusion | both |
| `Sources/CSQLite` | Vendored SQLite 3.54.1 + sqlite-vec v0.1.9, compiled statically (`scripts/vendor-sqlite.sh`) | both |
| `Sources/AudioCapture` | Core Audio process tap, browser process matching, PCM conversion, WAV writer | macOS only |
| `Sources/Transcription` | `SpeechAnalyzer` session wrapper and file feeder | macOS 26+ only |
| `Sources/Spike*` | `spike-claude`, `spike-vec`, `spike-tap`, `spike-stt` | see below |
| `App/` | XcodeGen spec and SwiftUI menu bar app (tap + live transcript) | macOS 26+ |
| `scripts/mock-anthropic.py` | Local streaming mock of the Messages API for transport tests | any |

## Setup on the Mac

1. Xcode 27 (Swift 6.4). Xcode 27 needs macOS Tahoe 26.6 or later. The app's minimum
   is macOS 26.0, so it runs on Tahoe and on macOS 27.
2. `brew install xcodegen`
3. `swift test` from the repository root. Expect all tests to pass, as on Linux.

The first build compiles the 9.5 MB SQLite amalgamation, which takes a minute.

## Runbook

Run on the MacBook Air, on battery, with Chrome and a Meet call open, as in real use.

### 1. Claude latency (`spike-claude`)

```bash
export ANTHROPIC_API_KEY=sk-ant-...      # Console API key
swift run -c release spike-claude --out results/claude.json
```

It sends 8 realistic live-answer requests per mode: `standard` (Sonnet 5.5, thinking off
via `between_tools`), `standard-adaptive` (Sonnet 5.5, adaptive thinking at low effort),
`fast` (Haiku 5.5) and `deep` (Opus 5.5). It prints time to first answer token, total
time, cache hits and cost. Expected spend is under $0.50, mostly from the Opus mode.
Use `--modes standard,fast` to skip Opus, or `--dry-run` to see the request bodies.

Sonnet and Opus requests send `fallbacks: "default"` with the beta header
`server-side-fallback-2026-07-01`, so a safety-classifier refusal is retried server-side.
Haiku 5.5 has no server-side fallback, so its requests omit it.

Decide: which Sonnet setting becomes the default. The API guide prefers adaptive
thinking at low effort; `between_tools` guarantees no thinking. Pick by p95 time to
first token, then by answer quality on the printed answers.

### 2. Vector store (`spike-vec`)

```bash
swift run -c release spike-vec --chunks 10000
swift run -c release spike-vec --chunks 30000
```

### 3. Browser audio tap (`spike-tap`)

Join a Meet call in Chrome (a second device or a test meeting with a video playing).

```bash
swift run spike-tap --list                                   # which processes play audio?
swift run spike-tap --browser chrome --strategy bundle --seconds 60
swift run spike-tap --browser chrome --strategy pids   --seconds 60
swift run spike-tap --browser chrome --strategy system --seconds 60
```

macOS asks once for "system audio recording" permission for your terminal app. If
nothing appears, enable it under System Settings, Privacy & Security. A strategy
works when the summary shows audible chunks and no gaps. Then record evaluation audio
for M2, ideally 30 minutes across a few real calls:

```bash
swift run spike-tap --browser chrome --strategy <best> --seconds 600 --wav recordings/call-01.wav
```

`recordings/` is git-ignored. It holds other people's voices, so get their consent.

Repeat with `--browser safari` if Safari matters.

### 4. Speech to text (`spike-stt`)

```bash
swift run -c release spike-stt recordings/call-01.wav --mode fast
swift run -c release spike-stt recordings/call-01.wav --mode accurate
swift run -c release spike-stt --live --browser chrome --strategy <best> --seconds 120 --mode fast
```

The first run may download Apple's English speech assets. File mode reports the
real-time factor. Live mode reports how far final results trail the audio; the budget
is 500 ms.

### 5. Menu bar app

```bash
cd App && xcodegen && open Jeeves.xcodeproj
```

Set your team under Signing & Capabilities, or keep "Sign to Run Locally". With
ad-hoc signing, macOS asks for audio permission again after every rebuild. Run, click
the ear icon in the menu bar, pick the browser and capture strategy, and press Start
listening. The window shows the live transcript and final-result lag.

Notes from the Linux numbers:

- Lexical (BM25) search dominates hybrid latency and grows linearly with corpus size,
  because common words match most chunks under OR semantics. The query builder now
  drops stopwords. If 30k-chunk numbers on the Mac exceed budget, M3 options are
  running the two searches on separate connections in parallel and capping BM25
  candidates per term.
- Vector search is exact (brute force) and costs about 0.7 ms per 1,000 chunks here.
  Apple silicon builds enable sqlite-vec's NEON path.

## Not yet verified

The macOS-only code (`AudioCapture`, `Transcription`, `SpikeTap`, `SpikeSTT`, `App/`)
passed a Swift syntax check on Linux but has not been type-checked against the macOS
SDK. The first Xcode build may need small fixes. The likeliest spots:

- Swift 6 `Sendable` diagnostics around the Core Audio IO block and AVFoundation types
  (mitigated with `@preconcurrency import AVFoundation`).
- Whether `CATapDescription()` with `bundleIDs` set (macOS 26) captures browser helper
  processes. This is exactly what the `bundle` strategy spike tests; `pids` and
  `system` are the fallbacks.
- `AnalysisContext.contextualStrings` assignment and the `SpeechAnalyzer` initializer
  defaults, written from Apple's documentation pages.
- Bundle-ID prefixes for browser helper processes, which `spike-tap --list` confirms.
